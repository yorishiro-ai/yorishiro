# SQLite モード

Yorishiro は PostgreSQL の代わりに SQLite で動作できます。
ローカルでの評価や、他の人とデータを共有しない単独のワークスペースに利用してください。

マルチテナント運用には SQLite を使わないでください。
すべてのデータを単一ファイルに保存し、データベース側ではテナントを分離しません。
複数のテナントで同じサーバーを使う場合は PostgreSQL が必要です。

## SQLite で動作するもの

- **エンティティの CRUD**。エンティティの作成、読み取り、更新、削除。
- **ベクトル検索**。埋め込みベクトルによる類似度検索（sqlite-vec）。
- **全文検索**。FTS5 `tokenize='trigram'` による文字n-gramのあいまい検索。
- **API キー認証**。API キーの作成と利用。
- **埋め込み同期**。PostgreSQL と同じ方法でのベクトル生成と保存。
- **テンプレートとスキーマの更新**。テンプレートからスキーマを作成し、更新内容を確認して取り込めます。
- **関連エンティティの検索**。`recall_context` で複数段階の関係をたどれます。
- **列の表示設定と推論の提案**(エンタープライズ)。
- **スナップショットと巻き戻し**。スナップショットからのエンティティ復元（PostgreSQL で作成されたスナップショットが必要）。

## SQLite で動作しないもの

- **マルチテナント**。SQLite は正確に1テナントのみをサポートします。テナント上限は1にハードコードされており、変更できません。
- **コンテンツフィルタリング**。`filter` クエリパラメータ（JSONB 包含）はエラーを返します。
- **マーケットプレイス**(エンタープライズ)。テナントをまたいで一覧と公開を行うため、SQLite ではエンドポイントが `501`(コード `backend_unsupported`)を返します。
- **名前付きアドバイザリロック**。SQLite では利用できません。infer-fill はワークスペースごとに一度に1ジョブだけ実行します。
- **SQLite 用スナップショット**。スナップショットの作成はサポートしていません。PostgreSQL で作成されたスナップショットなら SQLite で復元できます。

## 設定

SQLite DB でサポートするキュー構成は、別ファイルの SQLite キュー、または Redis 互換 (Valkey) キューです。
SQLite DB と PostgreSQL キューの組み合わせは利用できず、起動前に `ValidationFailed` として拒否します。
更新時に同じワークスペースの実行中 infer-fill ジョブが複数あると報告された場合は、ワーカーの完了を待ち、重複を解消してから更新を再試行してください。
ワーカーの実行中に、データベース上だけでジョブを停止扱いにしないでください。

Yorishiro はデータベース URL のスキームで SQLite を検出します。
`sqlite:/path` や `sqlite::memory:` を含め、`sqlite:` で始まる URL は SQLite のデフォルト設定を選びます。

```sh
export DATABASE_URL='sqlite:///var/lib/yorishiro/yorishiro.sqlite3?mode=rwc'
cargo run
```

SQLite のバックグラウンドジョブは、既定で別ファイル `sqlite:///var/lib/yorishiro/yorishiro_queue.sqlite3?mode=rwc` を使います。
アプリケーション用とキュー用の接続プールが同じ SQLite ファイルのロックを取り合い、ワーカーのジョブ取り出しが停止するため、ファイルを共有してはいけません。
`QUEUE_URL` がアプリケーション用ファイルを指している場合は、未処理ジョブを処理または移行し、別のキューファイルを指定してから起動してください。

接続は少なくとも 2 つ必要です。
`max_connections` が 2 未満の場合、サーバーは起動しません。

## 設定ファイル

本番用の SQLite 専用設定ファイルはありません。
`config/production.yaml` で `DATABASE_URL` に `sqlite://` URL を設定してください。
アプリケーションのパスを変更する場合は、`QUEUE_URL` に別の SQLite ファイルを指定してください。

## 認証

認証はテナント用の接続プールを経由せず、データベースに直接接続します。
行レベルのセキュリティはありません。
SQLite は単一テナントでのみ使用してください。
