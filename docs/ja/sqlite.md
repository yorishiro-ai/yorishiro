# SQLite モード

Yorishiro は PostgreSQL の代わりに SQLite で動作できます。自分のマシンで Yorishiro を試したり、他の人とデータを共有しない単独のワークスペースで使ったりするために用意されています。

マルチテナントホスティングには SQLite を使わないでください。すべてのデータを単一ファイルに保存し、データベースレベルでのテナント分離がありません。2つ以上のテナントが同じデプロイを共有する場合には PostgreSQL が必要です。

## SQLite で動作するもの

- **エンティティの CRUD**。エンティティの作成、読み取り、更新、削除。
- **エンティティ検索**。全エンティティのテキスト検索。
- **ベクトル検索**。埋め込みベクトルによる類似度検索。
- **全文検索**。埋め込みがないエンティティのテキスト検索。
- **API キー認証**。API キーの作成と利用。
- **埋め込み同期**。PostgreSQL と同じ方法でのベクトル生成と保存。
- **スナップショットと巻き戻し**。prior のスナップショットからのエンティティ復元（PostgreSQL で作成されたスナップショットが必要）。

## SQLite で動作しないもの

- **マルチテナント**。SQLite は正確に1テナントのみをサポートします。テナント上限は1にハードコードされており、変更できません。
- **JSONB フィルタリング**。`filter` クエリパラメータ（JSONB 包含）は利用できず、エラーを返します。
- **PostgreSQL SQL を必要とするエンタープライズ機能**。`unnest`、`CROSS JOIN LATERAL`、アドバイザリロックに依存する機能は利用できません。
- **SQLite 用スナップショット**。スナップショット機能は PostgreSQL 固有の SQL で動作します。PostgreSQL で作成されたスナップショットなら SQLite で復元できますが、SQLite でスナップショットを作成することはできません。

## 設定

例の SQLite 設定ファイルをコピーし、環境を指定します。

```sh
cp config/sqlite.yaml.example config/sqlite.yaml
export LOCO_ENV=sqlite
```

`config/sqlite.yaml` は `max_connections: 10` を設定します。少なくとも2つの接続が必要です。`max_connections` が2未満の場合、サーバーは起動を拒否します。

## 試してみる

通常通りサーバーを起動します。起動ログに、PostgreSQL 固有の SQL に依存するエンタープライズ機能が利用できないこと、ベクトル検索はこのバックエンドで動作することを通知します。

認証はテナントプールを経由せずデータベースに直接接続します。シンプルですが、行レベルのセキュリティがないことに注意してください。アプリケーションは単一のテナントが他のテナントのデータを改ざんしないと信頼します。テナントが1人しかいない場合、これは問題になりません。

## テスティング

テストスイートは PostgreSQL で実行されます。SQLite は手動検証用の環境です。変更を SQLite で検証するには以下を実行します。

```sh
export LOCO_ENV=sqlite
cargo run
```
