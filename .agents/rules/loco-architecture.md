# Loco and SeaORM architecture

This repository follows Loco 1.2.0 and SeaORM 2.0.4 conventions unless a documented platform or security requirement prevents it.

## Models

- `src/models/_entities/` is generated by `cargo loco db entities` and is never edited by hand.
- Application-owned model extensions live at `src/models/<table>.rs`, matching Loco's generator layout.
- `src/models/mod.rs` is limited to module declarations and visibility gates; domain logic does not live there.
- A large model may keep private implementation modules under `src/models/<table>/`, declared normally from `src/models/<table>.rs`.
- Model modules must not use `#[path]` declarations or zero-byte generator sentinels.
- Finders and table-owned persistence belong in the owning model module.
- State transitions and save hooks belong on `ActiveModel` where that API fits.
- Cross-table use cases may have a model-level facade, but must not introduce a repository layer that only wraps SeaORM.
- Response and request DTOs are transport types and do not belong in generated entities.

## Controllers and services

- Controllers authenticate, parse input, call model or use-case operations, and render responses.
- Controllers do not build ordinary entity queries when a named model finder can own the tenant and authorization constraints.
- `services/` is reserved for external integrations, protocol adapters, middleware, and orchestration that is not owned by one table.
- A service may own a transaction or workflow, but table-specific reads and writes remain model methods.
- MCP tool implementations remain under `src/services/mcp/`; `src/controllers/mcp.rs` only mounts the transport.

## Application lifecycle

- `src/app.rs` owns the Loco `Hooks` implementation and edition composition.
- Long-lived process work uses Loco lifecycle hooks or initializers and has an awaited shutdown path.
- Durable or retryable work uses Loco workers and queue providers rather than `tokio::spawn`.
- Application settings come from validated Loco configuration.
- Direct environment reads are limited to configuration loading and documented process-bootstrap requirements.

## Database connections

- SeaORM entity and query APIs are the default for reads and writes.
- `src/db.rs` owns the identity and tenant pools, RLS session setup, reset behavior, and transaction-scoped tenant context.
- The two-pool design is a security boundary because Loco's standard connection does not expose the pool lifecycle hooks required to reset tenant state.
- SQLite is single-tenant and does not emulate PostgreSQL RLS.

## Raw SQL

Raw SQL requires a reason from one of these categories:

- RLS, role, session, or connection lifecycle primitive.
- Security-definer authentication function.
- Advisory lock.
- Backend extension such as pgvector, sqlite-vec, FTS5, pg_trgm, or backend-specific DDL.
- Query shape that SeaORM cannot express without materially obscuring its semantics.
- Atomic write whose correctness depends on one database statement.
- Measured performance requirement recorded beside the query.

Use SeaORM for ordinary projections, filters, joins, updates, row locks, and transactions when its public API preserves the same behavior.

## Migrations and generation

- Migrations under `migration/src/` are hand-written with SeaORM Migration.
- Shared backend differences belong in `migration/src/helpers.rs` rather than per-migration copies.
- PostgreSQL-only RLS, grants, extensions, and trigger bodies may use raw migration SQL.
- `make entities` is the canonical entity-generation workflow and includes generated-secret hardening.
- PostgreSQL is the entity-generation source of truth; do not generate checked-in entities from SQLite.

## Project boundaries

- `ee/` remains at the repository root so `ee/LICENSE` scopes it.
- `src/app.rs` is the only base source file that may reference `crate::ee`.
- Request-time licence checks remain separate from Cargo feature composition.
- Generated entities and migrations are centralized because CE and EE compile as one application crate when the enterprise feature is enabled.
