# Knowledge

## Repository overview

This repository is mid-port from a hand-rolled `sqlx` + `sea-query` + `Engine`-generic data layer to [Loco](https://loco.rs).

## Repository layout

Root crate + `migration/` crate + `ee/` module. `src/models/` owns queries and record shapes; `src/controllers/` maps HTTP requests to actions; `services/mcp/` owns MCP tools (`YorishiroMcpServer` and `#[tool_router]` implementations). `ee/` mirrors `models/`, `controllers/`, and `services/` for enterprise features.

### Model ownership

- One table = one module under `src/models/<table>.rs`.
- `src/models/_entities/` is auto-generated by `cargo loco db entities`. Never edit by hand.
- Business logic lives alongside the generated entity in `<table>.rs`. No separate repository layer.
- Adding a table: write a migration under `migration/src/`, run `make entities`, add a module under `src/models/`.

### Not a model

- `migration/src/`, `templates/*.json`, and `src/db.rs` are database concerns, not model concerns. They stay outside `models/`.
- `src/db.rs` handles connection pooling, two-pool architecture (identity pool for control plane, tenant pool for RLS-scoped requests), and session primitives (`SET ROLE`, `RESET`, `set_config`).

### Raw SQL

Only where SeaORM cannot express it:
- JSONB containment (`data @> filter`)
- pgvector similarity search (`vec_distance_cosine`)
- Advisory locks
- Correlated aggregates with no entity column
- Writes whose correctness depends on executing as a single statement

Examples:
- `src/db.rs`: connection primitives (`SET ROLE`, `RESET`, advisory locks)
- `src/services/auth/authenticate.rs`: `authenticate_api_key($1)` — the SECURITY DEFINER function that bypasses RLS
- `src/services/embedding/sync.rs` and `src/tasks/resync_embeddings.rs`: pgvector `embedding` column operations
- `ee/services/tenant_auth.rs`: `authenticate_api_key($1, $2)` two-argument overload

### MCP placement

MCP is a service, not a controller. Route mounting (`src/controllers/mcp.rs::mount()`) is the one exception — it is a one-liner called from `Hooks::after_routes`.

## Architecture

- Loco + SeaORM + sea-query
- Two connection pools: `identity` (control plane, migration-role) and `tenant` (RLS-scoped). See `src/db.rs`.
- Entity API is the default path for reads and writes.

## SQLite

- Single-tenant only. No RLS.
- `src/db.rs::require_min_sqlite_connections(2)` — minimum 2 connections.
- Vector search via sqlite-vec (BLOB storage).
- ID generation: `before_save` hook calls `db::sqlite_generated_id()`.
- Embedding column lives in `content_entity_embeddings` table on both backends.
- FTS5 with `tokenize='trigram'` for fuzzy text search (pg_trgm equivalent on PostgreSQL).

### Migration helpers (migration/src/helpers.rs)

- `use_transaction()` — forces transaction on every backend.
- `uuidv7_pk(manager)` — `UUID PRIMARY KEY DEFAULT uuidv7()` on PG, `BLOB PRIMARY KEY` on SQLite.
- `uuid_col(manager, name)` — `UUID` on PG, `BLOB` on SQLite.
- `json_col(manager, name)` — `JSONB` on PG, `TEXT` on SQLite (sqlite-vec lacks `jsonb_text` type).
- `ts_tz_col(manager, name)` — `TIMESTAMPTZ` on PG, `TEXT` on SQLite.
- `timestamps(manager)` — returns `[created_at, updated_at]` column defs.
- `create_table_with_checks()` — creates table + CHECK constraints, backend-bridged.
- `enable_rls_with_policy()` — raw SQL for RLS. No-op on SQLite.
- `grant()` — per-table GRANT to `yorishiro_app`. No-op on SQLite.
- `pg_only(sql)` — PostgreSQL-only raw SQL. No-op on SQLite.
- `sqlite_only(sql)` — SQLite-only raw SQL. No-op on PostgreSQL.

## Error handling

- `YorishiroError` is the primary error type. Use `.internal()` for conversion.
- `YorishiroError::not_found()` for NotFound construction.
- `ResultExt` trait provides `.internal()` which wraps into `YorishiroError::Internal`.
- `into_http_parts()` converts errors to HTTP response components.

## Imports

- `use axum::http::StatusCode;` (never fully-qualified).
- Group order: std → external → workspace → crate-internal.

## Testing

- `tests/` is a plain Loco integration-test crate (one binary, no `#[path]` includes).
- `tests/requests/mod.rs` owns `close_app_pools`.
- Request tests using `request_with_create_db` **must** call `close_app_pools` before returning.
- Tests need PostgreSQL with `vector` and `pg_trgm` in `template1` (not just the deployment database). Loco's harness creates each test database via `CREATE DATABASE`, which copies `template1`.
- Tests need a non-superuser role (superuser bypasses RLS regardless of `FORCE`).

## Git workflow
